지정한 경로의 폴더/파일을 분석해 요약·정리한다. **읽기 전용 작업**이며 파일을 수정·삭제·생성하지 않는다.

## 입력

`/abstract-work` 뒤에 붙은 내용: $ARGUMENTS

- **경로가 있으면** 따옴표·`@` 접두어를 제거하고 바로 분석한다. 존재하지 않는 경로면 그 사실만 알리고 다시 입력받는다.
- **비어 있으면** "요약할 폴더 또는 파일 경로를 입력해주세요"라고 안내하고 멈춘다. 다음 메시지로 경로가 오면 곧바로 분석한다.

## 경로가 파일일 때

내용을 읽고 아래 3가지를 간략히 정리한다.

- **용도**: 이 파일이 무엇을 위한 것인지
- **내용**: 코드면 어떤 동작/역할인지, 문서면 어떤 내용인지
- **생성 일자**: 파일 시스템의 생성 시각(PowerShell `(Get-Item <경로>).CreationTime`). 확인 못 하면 "확인 필요"

## 경로가 폴더일 때

1. 폴더 구조를 파악한다. `.git`, `node_modules`, `__pycache__`, `.venv`, 빌드 산출물 등은 제외하고, 파일이 많으면 대표 파일 위주로 읽는다(범위를 줄였다면 그 사실을 밝힌다).
2. **파일별 소개**: 파일마다 한두 줄. 코드는 동작/역할, 문서는 내용. 바이너리·이미지 등은 종류만 적는다.
3. **마지막에 폴더 전체 요약**: 이 폴더가 무엇이고 어떤 작업이 진행되었는지(수정 시각·git 이력이 있으면 참고).

## 프로젝트라면: 추천 작업

대상이 프로젝트로 보이면(`package.json`, `pyproject.toml`, `.git`, 소스 구조 등) 분석 결과를 바탕으로 **더 수행하면 좋을 작업**을 추천한다.

- **추천만 한다.** 추천한 작업을 절대 스스로 실행하지 않는다. 실행은 사용자가 따로 요청할 때만 한다.
- 상급자(관리자) 권한이 필요하거나 위험한 작업(배포, 삭제·덮어쓰기, 운영 DB·서버 변경, 외부 전송, 권한/보안 설정 변경, `push --force` 등)은 항목 옆에 **⚠️ 경고**를 붙이고 왜 위험한지, 어떤 권한이 필요한지 안내한다.

## 작성 원칙

- 한국어, 결론 먼저, 간략하게.
- 읽지 못했거나 확신 없는 내용은 지어내지 말고 "확인 필요"라고 쓴다.
